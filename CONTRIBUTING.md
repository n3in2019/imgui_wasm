# Contributing to ImGuiWasm

Thanks for helping improve ImGuiWasm. Bug reports, focused fixes, documentation,
and compatibility improvements are welcome.

## Before you start

- Search existing issues and pull requests before opening a duplicate.
- Use an issue for substantial design changes so the approach can be discussed.
- Keep pull requests focused on one feature or fix.
- Never include build output, downloaded dependencies, virtual environments, or
  local configuration.

## Local setup

Install Git, CMake 3.10+, a C++17 compiler, Node.js, and Python 3.10+ for
binding regeneration (`dear_bindings` requires 3.10+). Then build from the
repository root:

```bash
cmake -B build
cmake --build build
```

The first CMake configure fetches the pinned Dear ImGui source into an ignored
local directory. The browser WASM replay twin is committed; regenerate it with
`python3 tools/build_wasm_twin.py` (requires Emscripten) after
changing `wasm/` or the opcode header.

## Required checks

```bash
cmake -B build
cmake --build build
./build/tests/core_cpp_tests
node --check frontend/imgui_wasm.js
node --check frontend/imgui_wasm_callstream.js
python3 -m py_compile tools/generate_bindings.py
git diff --check
```

Use clear commit messages and explain user-visible behavior, testing, and any
compatibility impact in the pull request.

## Generated bindings

The C API and metadata are generated by `dear_bindings`; the call-stream
artifacts are generated from that metadata:

- `include/imgui_wasm_opcodes.h`
- `tools/generated/callstream_schema.json`
- `wasm/generated/replay_switch.cpp`
- `include/imgui_wasm_capture.hpp`

Regenerate with:

```bash
python3 tools/dear_bindings/generate.py
```

This command fetches the pinned Dear ImGui and `dear_bindings` revisions into a
temporary directory. Include metadata and all generated output in the same
change so reviewers can reproduce it.

## Reporting security issues

Do not open a public issue for a vulnerability. Follow [SECURITY.md](SECURITY.md)
instead.
