# AGENTS.md — ImGuiWasm

## Build & Run

### C++ Core

```bash
cmake -B build
cmake --build build
./build/examples/example_core_cpp_callstream [bind_address]
```

The first configure fetches the pinned Dear ImGui into the ignored
`third_party/` directory (requires Git and network access).

Tests: `./build/tests/core_cpp_tests`.

### WASM Replay Twin

The browser twin artifacts (`wasm/imgui_wasm_replay.{js,wasm}`) are
committed and embedded at build time. Regenerate them after editing
`wasm/`, the opcode header, or the generated replay switch:

```bash
python3 tools/build_wasm_twin.py
cmake --build build
```

Requires an `em++`-style Emscripten driver on `PATH` (or `IMGUI_WASM_EMCC`).

### Upstream Bumps

```bash
python3 tools/bump_upstream.py <imgui-tag-or-sha>
```

Fetches the revision, re-pins it in CMakeLists.txt, the bindings generator,
and the vcpkg port, regenerates the bindings, rebuilds the twin, and runs
the tests. Re-running with the current pin is a full end-to-end pipeline
check (expect no diffs beyond the twin artifacts if the generators are
deterministic).

## Project Structure

| Component | Path | Description |
|-----------|------|-------------|
| **Core** | repo root | Pure C++17 core: HTTP/WebSocket server, call-stream capture and binary protocol, C ABI, embedded frontend, and internal Dear ImGui web backend. |
| **C lifecycle API** | `include/imgui_wasm.h` | Small public lifecycle API: `imgui_wasm_init`, `imgui_wasm_shutdown`, `imgui_wasm_new_frame`, `imgui_wasm_render`. |
| **Generated ImGui API** | `include/imgui_wasm_imgui.h` | Separate `dear_bindings`-generated Dear ImGui C API surface. Do not include this from `imgui_wasm.h`. |
| **imgui-wasm-cpp** | `include/imgui_wasm.hpp` | Thin C++ convenience wrapper (`imgui_wasm::Server`). It should not own backend internals or duplicate Dear ImGui runtime code. |
| **Call-stream capture** | `include/imgui_wasm_capture.hpp` | Internal generated wrappers that transparently capture supported application `ImGui::` calls. |
| **WASM replay twin** | `wasm/` | Browser-side Dear ImGui compiled via Emscripten; it replays captured calls to regenerate draw data locally. Regenerate with `tools/build_wasm_twin.py`. |
| **Call-stream artifacts** | `tools/generated/`, `include/imgui_wasm_opcodes.h` | Generated opcode table, arg schema, and replay switch. Regenerated by `generate_bindings.py`. |

## Architecture

1. **Core** (repo root) owns transport, server state, call-stream serialization, and browser-facing messages.
2. **Internal ImGui backend** (`src/imgui_backend.cpp`) owns the Dear ImGui context and bridges input/frame/render work into the core through `imgui_wasm_core_api_t`.
3. **Public lifecycle API** (`imgui_wasm.h`) stays small and language-neutral. Users call init/shutdown/new_frame/render only.
4. **The C++ wrapper** should stay thin. It calls the lifecycle API directly; the `imgui_wasm.hpp` capture redirect is the only ImGui-surface magic it owns.
5. **Browser frontend** (`frontend`) renders draw commands via WebGL.
6. **Multi-client**: each WebSocket client is assigned a unique `u32` client ID. Per-client state includes display size, delta/frame tracking, and clipboard. Input from any client drives the shared ImGui context; the most recently active client determines the display size.

## Generated API Rules

- Do not handwrite broad ImGui API wrappers in C++.
- Regenerate with:

```bash
python3 tools/generate_bindings.py
```

- The generator consumes metadata from `tools/dear_bindings/`.
- Keep `include/imgui_wasm.h` lifecycle-only. Keep generated ImGui declarations in `include/imgui_wasm_imgui.h`.

## Key Gotchas

- **Dear ImGui Fetch**: CMake clones Dear ImGui into `third_party/imgui` on first configure if missing. This directory is local dependency state and should not be committed.
- **Generated binding files**: `include/imgui_wasm_imgui.h`, `src/imgui_wasm_imgui.cpp`, and `tools/dear_bindings/*.json` are committed generated inputs/outputs used by language bindings.
- **Frontend changes**: changes under `frontend/*` require `cmake --build build` to re-embed.
- **Frame hash determinism**: `callstream_frame_hash` (`src/state.cpp`) drives identical-frame suppression. It MUST be deterministic across frames and runs, or every frame is re-sent.
- **OES_element_index_uint**: required for WebGL 1 contexts.
- **Local-only directories**: do not commit `build/`, `.venv/`, `third_party/`, or `third_party/`.

## Binary Protocol

All values are little-endian. First byte is message type.

### Server-to-client messages

- `0x02` = Texture: id (`u64`), width, height, pixel data length, RGBA pixels.
- `0x06` = Client ID assignment: assigned client id (`u32`). Sent once on WebSocket connect before any other messages.
- `0x0a` = Capability hello: magic `"IMGW"` (4 bytes) + server capabilities (`u32`): bit 0 draw-data transport, bit 1 call-stream; remaining bits reserved (bit 2 was never-implemented compression). Sent right after `0x06`; no further server state until the client acks.
- `0x18` = Clipboard text: text length (`u32`), UTF-8 text bytes.

### Client-to-server messages

All client messages include a `u32` client ID at offset 1 (after the message type byte).

- `0x10` + client_id (`u32`) + x (`f32`) + y (`f32`) = Mouse move.
- `0x11` + client_id (`u32`) + button (`u8`) = Mouse down.
- `0x12` + client_id (`u32`) + button (`u8`) = Mouse up.
- `0x13` + client_id (`u32`) + dx (`f32`) + dy (`f32`) = Mouse wheel.
- `0x14` + client_id (`u32`) + key (`u16`) = Key down.
- `0x15` + client_id (`u32`) + key (`u16`) = Key up.
- `0x16` + client_id (`u32`) + character (`u32`) = Text input.
- `0x17` + client_id (`u32`) + w (`f32`) + h (`f32`) + scale (`f32`, optional) = Resize. CSS-pixel canvas size; `scale` is the client `devicePixelRatio` (font/render density). Legacy 13-byte messages omit `scale` (treated as "no new information", keeping the client's last known scale).
- `0x18` + client_id (`u32`) + text length (`u32`) + UTF-8 text = Clipboard text from client.
- `0x1a` + client_id (`u32`) + capabilities (`u32`) = Capability ack, in response to `0x0a`. Client capability bits: 0 WebGL, 1 Worker + OffscreenCanvas, 2 SharedArrayBuffer (cross-origin isolated), 3 WebGPU. Must lead its WebSocket message; trailing records (early input batched behind the ack) are dropped.

### Call-stream transport

The server streams the sequence of ImGui API calls instead of rendered draw data. The browser replays them against a WASM-compiled Dear ImGui twin to regenerate draw data locally. This drops per-frame bandwidth from KB of vertices to tens of bytes of calls, and idle frames cost ~nothing.

**Resolution model:** each browser twin replays at its own real resolution — `DisplaySize` is its canvas in CSS pixels and fonts rasterize at its `devicePixelRatio` (`ImFontConfig::RasterizerDensity`; density does not alter metrics, so layout matches the server's). The server-side layout (header `dsw/dsh`) follows the most recently active client's resize and stays authoritative for input hit-testing; `fbsx/fbsy` carry that client's scale. Secondary clients with different window sizes render their own native layout. Positional input (mouse move/buttons/wheel) from a client is held for one frame whenever the current layout was computed at a different canvas size: the server re-layouts to the interacting client (tmux-style) and ImGui hit-tests against the previous frame's geometry, so every positional event is applied against a layout that already matches its sender's window. Keyboard and text input never wait on geometry.

**Host integration:** C++ hosts use the ordinary Dear ImGui `ImGui::` API.
`imgui_wasm.hpp` transparently redirects supported rendering calls through the
internal capture surface. Getters, queries, and unsupported calls retain their
native/server-side implementations.

**Additional server-to-client messages (call-stream mode):**

- `0x07` = Call-stream frame: header (6 × `f32`: dpx,dpy,dsw,dsh,fbsx,fbsy) + `frame_id` (`u32`) + `call_count` (`u32`, hint; may be 0 = unknown) + opcoded calls. Each call: `opcode` (`u16`) + args per the schema in `tools/generated/callstream_schema.json`.
- `0x09` = String-table update: `count` (`u32`) + `count` × { `id` (`u32`), `len` (`u32`), UTF-8 bytes }. Sent on connect (full table replay) and whenever new strings are interned.

**WASM twin build:** regenerating `wasm/imgui_wasm_replay.{wasm,js}`
requires Emscripten (`em++` on PATH, or set `IMGUI_WASM_EMCC` to an
`em++`-style C++ driver; the C driver cannot link the twin's libc++ usage):
`python3 tools/build_wasm_twin.py`.

## After Editing

1. If you edited `src/*`, `include/*`, or generated ImGui API files, run `cmake --build build`.
2. If you edited binding metadata or generator code, run `python3 tools/dear_bindings/generate.py`, then rebuild the core.
3. If you edited `wasm/*`, the opcode header, or generated replay switch, run `python3 tools/build_wasm_twin.py` to regenerate the WASM twin, then rebuild.
4. Verify end-to-end when behavior changes: run the example (`./build/examples/example_core_cpp_callstream`) and open `http://127.0.0.1:8888`.
